# AGENTS.md — operating rules for AI coding agents

> Single source of truth for every agent (Claude Code, DeepSeek Harness, Codex, Cursor, …).
> Keep this file short. Details live in the files linked below and are read **on demand**.

## 0. Before anything
1. Run `.agent/scripts/kit-context` (Claude Code does this automatically at session start).
2. Read `.agent/memory/STATE.md` and, if on a task branch, the task file `.agent/tasks/TASK-NNN-*.md`.
3. If `.agent/context/PROJECT.md` still contains `TODO`, follow **kit-onboard** (or **kit-migrate** first on an existing repo with legacy agent rules) before writing product code.

## 2. Core workflow (never skip a step) — details: `.agent/rules/core/workflow.md`
```
source / plugin planning ─▶ kit-task start ─▶ 1 understand ─▶ 2 clarify (ask!) ─▶ 3 solution ─▶ 4 tests first (red)
   ─▶ 5 implement + checkpoint ─▶ 6 verify ─▶ 7 document (living docs) ─▶ 8 kit-task finish ─▶ human merge
             ▲                                                              │
             └────────────────────── kit-task rollback ◀────────────────────┘
```
- **No code without a task. No task without acceptance criteria. Unclear → ask, never guess.** Low-risk unknown → `ASSUMPTION:`; only a human marks it `CONFIRMED:`.
- Never cite an id, file, function or library API you have not seen — `kit-trace` and CI catch invented ids.
- Work **only on a task branch** (`<type>/TASK-NNN-slug`, gitflow: `.agent/rules/core/git-workflow.md`). `main` (go-live only), `develop` (integration), `staging`, `release/*`, `hotfix/*` are protected.
- Create documents with `.agent/scripts/kit-new` — never invent the skeleton.
- Small steps: change → `kit-run check` → `kit-task checkpoint "<what is now working>"`. Same error 3× → rollback, LESSONS.md, re-plan.
- **Full-stack Developer on Vertical Slices (Size M: 150–350 LOC)**: One agent implements DB + Logic + API + UI + Tests for a feature. Never split tasks horizontally.
- Done = `kit-task verify` passes + `.agent/checklists/definition-of-done.md`. Then `kit-task finish`. CI re-runs `kit-task verify` on the PR.

## 3. Hard rules (also enforced by hooks / git hooks / CI)
- Never read, print, create or commit secrets: `.env*` (except `.env.example`), keys, certs, credentials, tokens. Add config names to `.env.example`; a human sets values.
- Never bypass checks (`--no-verify`, disabling hooks, skipping tests, weakening lint rules, deleting failing tests).
- Never push to protected branches, force-push, or rewrite shared history. Rollback only via `kit-task`.
- No deploy / publish / infra / production-data commands — a human runs those.
- Do not edit guardrails: `.agent/hooks/`, `.agent/githooks/`, `.claude/settings.json`, CI gates. Propose changes instead.
- Do not add dependencies without stating why in the task file; prefer the standard library / existing deps.
- Follow `.agent/rules/` (project > stack > core). If a linter/formatter disagrees with you, the tool wins.
- Local containers only through `kit-run up|down|logs`; deleting volumes/images needs a human.

## 4. Context discipline (keep sessions small)
- **One task per session.** Before the context gets large, or when done: run **kit-handoff**, then start a new session.
- Delegate wide reading to sub-agents when supported (`explorer`, `qa-engineer`, `security-reviewer`, `code-reviewer`) and keep only summaries.
- Prefer installed code-intelligence / LSP / MCP tools or targeted grep over reading whole files. Read line ranges only.
- **Parallel agents:** `kit-task start TASK-NNN --worktree`, then a new session in `../<repo>-TASK-NNN` (overview: `.agent/scripts/kit-board`).
- Persist durable facts in task logs, `STATE.md`, `LESSONS.md`, or an ADR — never rely on chat memory.

## 5. Documentation & reporting
- Docs language: `docs_language` in `.agent/project.yaml`.
- End of every working session: `kit-daily` → `docs/daily/<YYYY-MM>/<date>.md`.
- Every non-trivial choice → `kit-adr` → `docs/adr/NNNN-*.md`.
